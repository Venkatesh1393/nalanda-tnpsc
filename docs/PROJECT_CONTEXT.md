## 1. Vision

*Source: `PRD.md` §1-2, `CompetitorAnalysis.md`, `UserPersonas.md`*

Tamil Nadu produces one of India's largest pools of government-exam aspirants, yet preparation today is fragmented across WhatsApp groups, YouTube, printed guides, and city-concentrated coaching centers — leaving rural/tier-2-3 aspirants structurally disadvantaged by access, not ability.

**Nalanda TNPSC's vision:** become the most trusted, AI-guided preparation companion for every TNPSC aspirant — from a first-time Group 4 candidate to a repeat Group 1 Mains candidate — combining structured content, adaptive practice, and personalized AI mentorship in Tamil and English, at a price every aspirant can afford.

**Business goals (phased):** MVP on Group 4/VAO/Group 2-2A prelims (0-6mo) → Group 1/Police/Forest/TRB + AI mains evaluation (6-12mo) → institutional/B2B licensing + scale (12-24mo) → adjacent state PSCs + multi-state expansion (24-36mo).

**Key personas** (`UserPersonas.md`): Priya (college student, price-sensitive, Tamil-first, low bandwidth), Karthik (working professional, time-scarce), Divya (full-time repeat Group 1 aspirant, needs Mains feedback), Selvam (coaching-center student, hybrid offline+digital), Rajendran (coaching-center owner, B2B buyer).

**Closest competitor:** Vetri App — already claims "AI-powered TNPSC" positioning. Differentiation must come from execution depth (real adaptive difficulty, AI mains evaluation, community, transparent pricing), not the tagline alone.

## 2. Features

*Source: `PRD.md` §7-§10, `Smart_Practice.md`, `Learn_Module.md`, `Landing_Page_Design.md`, `Onboarding.md`*

**Core modules:** Auth (Google/Email OTP), Onboarding (Language → Exam → Target → Study Hours → Weak Subjects → AI Study Plan), Learn (Subjects → Topics → Subtopics → Videos/PDF), Practice (Topic Quiz, **100 Questions** signature mode, Sectional, Mock, PYQ, adaptive difficulty, hints, AI Explanation, Memory Tricks), Live Exams (scheduled cohort-wide mocks — deliberate whitespace vs. competitors), Current Affairs (daily/weekly/monthly, AI-summarized), Analytics (14 distinct graphs, see §11), Community (doubt forum), Bookmarks (pure index, never a content copy), Payments/Subscription (Free/Plus/Pro/Institutional), Notifications, Settings.

## 3. Architecture

*Source: `Architecture.md`*

**Style:** Modular monolith backend (Routes → Controllers → Services → Repositories → Models), not premature microservices. Three independent frontend clients (Website, Student Dashboard `frontend/`, Admin Panel `admin/`) plus `mobile/`, all against one versioned REST API (`/api/v1`).

**Key flows:**
- **Auth:** Firebase (Google OAuth + custom-built Email OTP) verifies identity → backend issues its own short-lived JWT (15min) + rotating refresh token (HttpOnly cookie) — see §6 for full detail.
- **AI:** Synchronous path (doubt chat, adaptive difficulty — cached, fast) vs. asynchronous/queued path (Mains evaluation, current-affairs summarization). All prompts live as versioned files in repo-root `prompts/`, never inline strings.
- **Payments:** Razorpay order created → client checkout → **activation gated on the signature-verified webhook**, never the client callback alone (closes the exact billing-trust failure mode seen in Testbook/Byju's per `CompetitorAnalysis.md`).
- **Deployment:** Static hosting + CDN for frontend/admin; containerized, autoscaled backend; MongoDB Atlas managed replica set.
- **Caching:** Redis for OTP/session/rate-limits, AI response cache, current-affairs/leaderboard cache. Analytics/Leaderboards are materialized views, never computed live.

## 4. Database

*Source: `Database.md` — MongoDB Atlas*

**23 collections**, clustered: Identity (Users, Profiles), Content Taxonomy (Subjects, Topics, Subtopics, StudyMaterials, Videos), Testing Engine (Questions, QuestionAttempts, MockTests, LiveExams), Personalization/Analytics (StudyPlans, Analytics, Bookmarks, Leaderboards), CurrentAffairs, Commerce (Subscriptions, Payments), Engagement (Notifications, Badges, Achievements), AI (AIHistory).

**Key architecture decisions:**
- **Question Options are embedded** in Questions (not a separate collection) — small, bounded, always read together.
- **Live Exams never embed a registrant list** (unbounded-array anti-pattern) — registration derives from QuestionAttempts + an atomic counter.
- **Analytics/Leaderboards are materialized**, refreshed by background jobs, capped (top-100 for leaderboards).
- **Sharding candidates:** QuestionAttempts and AIHistory (hashed on `userId`) once volume demands it — not needed at MVP.
- **`isCorrect` is never returned** by any question-listing API — closes an answer-leakage gap.

## 6. Authentication

*Source: `Authentication.md`*

**Originally fully passwordless** for every individual and institution-owner identity — Google Login or custom-built Email OTP (Firebase has no native 6-digit-code primitive, so this is hand-built then bridged to Firebase via Admin SDK). The one long-standing exception: institutional staff invites (`Registration_Flow.md` §6.4) use email+password, since that's a different trust model (owner-initiated, not self-serve).

**2026-08-01 update — a second, real exception now exists.** A build instruction asked for real Firebase Email/Password auth in a way that conflicted with the passwordless mandate above; asked directly, the user chose to add it as a genuine third sign-in option **alongside** Google + Email OTP, not replace either. So as of this date: individual users can authenticate via Google, Email OTP (still mocked — no real backend OTP module exists), *or* real Firebase Email/Password — three live paths, one of them a password. `docs/Authentication.md` itself was not rewritten to reflect this (see §13's cross-document note) — treat its "no password exists anywhere in this system" line as accurate for the *original* two paths and the product's stated design intent, not as a literal description of everything currently in the codebase. No password-reset UI was built for this new path (Firebase's own reset-email flow isn't wired up either) since it wasn't requested — a real, disclosed gap if this path sees real usage.

**Session model:** Nalanda-issued JWT (role + subscriptionTier claims, 15min TTL, in-memory only on client — never localStorage) + rotating refresh token (HttpOnly/Secure/SameSite cookie, reuse-detection revokes the whole session family on replay). Roles (`user`/`moderator`/`content_editor`/`admin`/`support`) are strictly independent from subscription tiers (`free`/`plus`/`pro`/`institutional`) — two separate JWT claims, two separate middleware checks, always.

**No password reset exists** — reframed as "Account Recovery" (email-change re-verification, support-assisted recovery for fully-lost access, logout-all for suspected compromise).

**Implementation status:** the frontend Login/Register/Verify Email flow is built; Google Login and the new Email/Password path are **real** as of 2026-08-01 (real Firebase Web SDK + real backend verification + real MongoDB sync — see §14); Email OTP remains **mocked** (`services/authService.ts`'s OTP functions — no Redis-backed backend OTP module exists yet). When an earlier session was asked to build a conventional "Forgot Password"/"Reset Password"/"Verify Mobile" auth module, the user was asked to confirm against this doc's passwordless mandate and explicitly chose to follow it: no Forgot/Reset Password pages, no Verify Mobile page (mobile isn't a verified identity in this product at all) — that decision still stands; no password-reset flow was added even for the new Email/Password path.

## 7. UI Design

*Source: `UI_Design_System.md`, `Landing_Page_Design.md`*

**Brand thesis:** a specific slice from each reference, not their surface look — Apple's restraint/whitespace, Stripe's data precision + gradient-as-accent, Linear's speed + best-in-class dark mode, Notion's calm reading surfaces, Duolingo's celebration *stripped of mascots* (dignified for an adult exam audience), Testbook's exam-taking conventions rebuilt with higher craft.

**Color system:** Primary = "Nalanda Indigo" (`#4A3FBF` light / `#7A70E8` dark, independently tuned, never inverted). Two **reserved, single-meaning** accents: **AI Teal** (`#1FB6A8`) exclusively for AI features, **Sangam Gold** (`#B5872A`) exclusively for premium/achievement — never reused for anything else.

**Typography:** Inter (Latin) + Anek Tamil (Tamil), weight-matched. Full scale (display → overline) implemented as Tailwind theme tokens.

**Motion principle:** `motionCelebratory` (spring) reserved for genuine, rare milestones only (a badge unlock, finishing a full revision queue) — never routine UI, or it gets cheapened.

**Implementation status:** fully built in `frontend/` — design tokens, the complete reusable component library, and the public site chrome (Navbar, Footer) are all implemented and verified; see §14.

## 9. AI Features

*Source: `PRD.md` §10, `Architecture.md` §5, `Smart_Practice.md` §4-§6, §11*

1. Personalized Study Plan Generator (adapts to falling behind/ahead)
2. Adaptive Practice Engine (scoped to Topic Quiz + 100 Questions only — never Sectional/Mock/PYQ, which must stay faithful to real exam conditions)
3. Weak-Area Detection
4. AI Doubt-Resolution Chatbot (Tamil/English, escalates to community on low confidence)
5. AI Mains Answer Evaluation (rubric-based: structure, relevance, coverage, language — Pro tier only)
6. Current Affairs Summarizer & Relevance Tagger
7. Performance Prediction / Rank Estimator
8. Voice-Based Q&A (Tamil)
9. Lightweight mock-test integrity signals (self-awareness only, explicitly non-punitive)
10. Smart Revision Scheduler (spaced repetition — pulls from bookmarks *and* wrong answers automatically, no manual bookmarking required)

**Hints vs. AI Explanation:** hints nudge before an answer is submitted; explanations only appear after, preserving practice integrity. **Memory Tricks** are a separate, curated/AI-suggested-but-human-reviewed mnemonic layer, kept free even on the free tier.

## 10. Analytics

*Source: `Analytics.md`*

**14 views**, all reading one materialized `Analytics` document (never computed live from raw attempts, except Subtopic Analytics which is a documented exception): Overall → Subject → Topic → Subtopic (drill-down hierarchy), Accuracy, Speed (vs. cohort benchmark), Heatmaps (topic × difficulty grid — single-hue scale, never traffic-light colors), Weak Areas *and* Strong Areas (equal visual weight — confidence-building is a real persona need, not an afterthought), Expected Score (range-band, never false-precision), Rank Prediction (bell-curve position), Study Time, Consistency (calendar heatmap), AI Recommendation (synthesizes all of the above into one prioritized, traceable action).

**Rule enforced everywhere:** any number from too small a sample gets an explicit disclaimer, never presented with false confidence.

**Implementation status (2026-08-03, Step 47):** the shipped Analytics page is still the single-page, 10-chart dashboard (not this doc's full 14-view drill-down), but every chart is now backed by a real `analytics` backend module computing live MongoDB aggregations over `QuestionAttempt`/`PracticeSession`/`LearningProgress` — no materialized `Analytics`/`StudentAnalytics` background job exists (that collection, modeled since Step 42, stays dormant; a documented, deliberate exception to this doc's "always materialized" rule at the current data volume). Classification (Strong/Good/Needs Improvement/Weak/Not Enough Data) and the Weak-Areas priority ranking are transparent, rule-based formulas (`backend/src/services/analytics.service.ts`'s header comment), never AI. See `MASTER_ROADMAP.md`'s Step 47 entry and `PROJECT_CONTEXT.md` §14 for full detail.

## 11. Coding Standards

*Source: `CLAUDE.md`, `FolderStructure.md`, established conventions in `frontend/`*

- Always TypeScript, always production-ready — no dummy/mock data in the actual product (design-system previews are the one explicit exception, clearly labeled as such).
- Clean architecture / SOLID: one middleware per concern, repositories are the *only* layer that queries MongoDB, controllers stay thin.
- No code duplication across `frontend/`/`admin/`/`mobile/` — shared logic goes in a `shared/` package (per `FolderStructure.md`); within `frontend/`, the `api/` (transport) vs `services/` (domain) split serves the same purpose.
- ESLint (flat config, typescript-eslint + react-hooks + react-refresh) + Prettier (with `prettier-plugin-tailwindcss`) — `eslint-config-prettier` always last so the two never fight.
- `components/ui/` is **exclusively shadcn-CLI-generated** — excluded from lint/prettier; any hand-authored primitive (e.g. `Typography`) lives directly in `components/` instead, never inside `ui/`.
- Every subscription/billing state change is idempotent and webhook-confirmed, never trusted from a client callback alone.
- Bilingual (Tamil/English) is a first-class requirement everywhere, not a translation afterthought.
